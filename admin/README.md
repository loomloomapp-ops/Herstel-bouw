# Панель керування — Herstel & Bouw

Редагування послуг і проєктів без бази даних: адмінка пише напряму у
`data/services.json` та `data/projects.json`, а сайт читає ці файли.

## Що потрібно від хостингу

- PHP 8.0+ (на Hostinger є за замовчуванням, нічого вмикати не треба)
- права на запис для тек `data/`, `data/.backups/`, `admin/`, `admin/storage/`
  та `images/projects/` (зазвичай `755` — стандартні права після заливки по FTP)
- розширення GD або нічого — без нього завантаження працює, просто великі
  фото не зменшуються, а лягають як є

Розширення бази даних, composer чи Node не потрібні.

## Перший запуск

1. Залийте всі файли на хостинг зі збереженням структури тек.
2. Відкрийте `https://ваш-домен/admin/`.
3. Придумайте пароль (мінімум 10 символів) — він збережеться хешем
   у `admin/config.php`.

**Зробіть крок 3 одразу після заливки.** Доки пароль не встановлено,
форму створення пароля бачить будь-хто, хто знає адресу.

Забули пароль — видаліть `admin/config.php` і повторіть крок 2.

## Що можна редагувати

**Послуги** — блок «Onze diensten» на головній. Назва й опис двома мовами,
мініатюра, посилання. Порядок змінюється перетягуванням; номери `01…10`
перераховуються автоматично.

**Проєкти** — картки на головній, каталог `projects.html` і сторінки
`project.html?id=…`. Тексти двома мовами, категорія, обкладинка, список
робіт, характеристики, галерея.

**Відгуки** — блок «Beoordelingen» на головній. Відвідувачі пишуть їх
самі через форму на сайті; на сайт вони потрапляють лише після вашого
підтвердження.

**Партнери** — блок «Onze partners» під відгуками. Назва компанії, опис
двома мовами, фото й адреса сайту. Клік по картці відкриває сайт партнера
в новій вкладці. Поки жодного партнера не додано, блок на сайті не
показується взагалі — порожньої смуги із заголовком не буде.

Адресу можна писати без `https://` — панель допише сама. Поле можна лишити
порожнім: тоді картка просто не буде посиланням.

Зміни застосовуються на сайті одразу після натискання **Зберегти**.

## Завантаження фото

У будь-якому полі із зображенням натисніть **Вибрати зображення** — у вікні,
що відкриється, є кнопка **Вибрати фото з комп'ютера** і зона для
перетягування. Можна кидати кілька файлів одразу; кожен іде окремо, тож одне
відхилене фото не зриває решту. Завантажене одразу підставляється в поле.

Фото лягають у `images/projects/` і залишаються там назавжди — вони доступні
в усіх полях, не тільки в тому, з якого їх завантажили.

| Правило | Значення |
|---|---|
| Формати | JPG, PNG, WebP |
| Максимум | 20 МБ на файл |
| Розмір | більше за 2560 px по довшій стороні — зменшується автоматично |
| Назва | латиниця з назви файлу; кирилиця транслітерується |
| Збіг назв | не перезаписує: другий `keuken.jpg` стане `keuken-2.jpg` |

Тип файлу визначається за вмістом, а не за розширенням, тож перейменований
скрипт із `.jpg` на кінці буде відхилено. SVG не приймається свідомо — він
може містити код.

**Важливо:** завантажені фото живуть на сервері й не потрапляють у git.
Якщо колись розгортатимете сайт із чистої копії репозиторію, спершу
скопіюйте `images/projects/` зі старого сервера.

## Як працює модерація відгуків

1. Відвідувач натискає «Schrijf een beoordeling» на головній і надсилає форму.
2. Відгук отримує статус **Очікує** і на сайті не показується.
3. У панелі на вкладці **Відгуки** з'являється помаранчева крапка й лічильник.
4. Відкриваєте відгук → **✓ Опублікувати** або **✕ Відхилити** → **Зберегти**.

Текст можна редагувати перед публікацією (виправити помилку, скоротити) і
дописати переклад: відвідувач пише однією мовою, друга спочатку дублює її.

Відхилені відгуки не видаляються — вони лишаються в панелі під фільтром
«Відхилені», тож рішення завжди можна змінити.

### Захист від спаму

| Механізм | Що робить |
|---|---|
| Прихована пастка (honeypot) | Бот заповнює невидиме поле → відгук мовчки відкидається |
| Заборона посилань | Текст із `http://`, `www.` чи HTML-тегом не приймається |
| Обмеження частоти | 1 відгук на хвилину і не більше 5 на добу з однієї адреси |
| Ліміт черги | Понад 300 неперевірених відгуків — прийом тимчасово зупиняється |
| Довжина | Мінімум 20, максимум 2000 символів |

### Де що лежить

`data/reviews.json` — **публічний** файл, який читає сайт. Містить лише
схвалені відгуки й тільки ті поля, що виводяться на сторінці.

`admin/storage/reviews.php` — **приватний** файл з усіма відгуками,
включно з неперевіреними, відхиленими та e-mail адресами авторів. Він
недоступний ззовні: закритий і через `.htaccess`, і власним PHP-захистом,
тож навіть за прямим запитом віддає порожню відповідь. E-mail автора
ніколи не потрапляє в публічний файл.

Резервні копії відгуків з тієї ж причини зберігаються не в `data/.backups/`,
а в приватній теці `admin/storage/backups/`.

## Заявки з форм

Усі чотири форми сайту — «Offerteaanvraag» на головній, калькулятор,
форма на `projects.html` і «Sollicitatie» на `vacancies.html` —
надсилаються на **herstelenbouw@gmail.com**.

Обробник — `lead-submit.php` у корені сайту. Він працює на самому хостингу,
без сторонніх сервісів: лист іде через пошту Hostinger від адреси
`noreply@herstelenbouw.nl`, а **Reply-To** підставляється з e-mail
відвідувача, тож відповідь із поштової програми піде одразу клієнту.

Резюме (`CV`) з форми вакансій приходить вкладенням: приймаються PDF, DOC,
DOCX і RTF до 8 МБ. Тип перевіряється за самим файлом, а не за назвою.

### Копія кожної заявки

`admin/storage/leads.php` — **приватний** архів останніх 300 заявок
(та сама схема захисту, що й у відгуків: `.htaccess` плюс `<?php exit;`).
Файли резюме лежать поруч, у `admin/storage/leads/`.

Архів існує на випадок, якщо лист колись не дійде: у ньому видно і саму
заявку, і поле `mailed` — чи прийняв сервер лист до відправки. Дістати їх
можна через FTP; у панелі керування вони не показуються.

### Захист від спаму

- приховане поле-пастка (`_honey`): бот, який його заповнить, отримує
  звичайне «дякуємо», але заявка нікуди не йде
- одна заявка на хвилину і не більше 10 на добу з однієї IP-адреси
- обов'язкові ім'я та щонайменше один спосіб зв'язку

### Щоб змінити адресу отримувача

Один рядок на початку `lead-submit.php`:

```php
const HB_LEAD_TO = 'herstelenbouw@gmail.com';
```

Адресу відправника (`HB_LEAD_FROM`) міняти не варто — вона мусить
лишатися на домені `herstelenbouw.nl`, інакше пошта Gmail вважатиме лист
підробкою.

## Свідомі обмеження

| Обмеження | Причина |
|---|---|
| Категорію проєкту можна вибрати лише з п'яти наявних | Кнопки-фільтри на `projects.html` — статична верстка; нова категорія не мала б свого фільтра |
| Поле «Бюджет» зберігається, але не виводиться | Так було й до адмінки — `js/main.js` показує лише тривалість, тип і рік |

## Безпека

- пароль зберігається як `password_hash()`, не у відкритому вигляді
- 6 невдалих спроб → блокування IP на 15 хвилин
- сесія завершується після 8 годин без активності
- усі зміни захищені CSRF-токеном
- `config.php`, `lib/`, `storage/` і `data/.backups/` закриті через `.htaccess`,
  а також не віддають вміст навіть якщо сервер проігнорує `.htaccess`

## Розгортання: чому git не чіпає дані

Сайт живе на Hostinger у `~/domains/herstelenbouw.nl/public_html` і оновлюється
через `git pull`. Але вміст сайту редагує власник через панель — просто на
сервері. Якщо дати git волю, чергова заливка мовчки затерла б його правки.

Тому на сервері п’ять файлів позначені як `skip-worktree` — git їх бачить,
але ніколи не перезаписує:

```
data/services.json      data/reviews.json
data/projects.json      data/partners.json
admin/storage/reviews.php
```

Перевірити: `git ls-files -v | grep '^S'`

**Наслідок:** зміну вмісту через git на сервер не доставити — і це навмисно.
Вміст змінюють у панелі, а git возить тільки код, стилі й зображення.

Якщо вміст усе ж треба залити з git (наприклад, після переїзду на новий
хостинг), порядок такий:

```bash
# 1. Спершу забрати те, що власник відредагував на сервері, до себе в git —
#    інакше його робота зникне
scp -P 65002 сервер:.../data/services.json ./data/

# 2. Зняти захист, залити, повернути захист
ssh сервер 'cd .../public_html && git update-index --no-skip-worktree data/services.json'
ssh сервер 'cd .../public_html && git pull --ff-only'
ssh сервер 'cd .../public_html && git update-index --skip-worktree data/services.json'
```

Фотографії, завантажені через панель, у git не потрапляють. Перед
розгортанням із чистої копії репозиторію скопіюйте `images/projects/`
зі старого сервера.

## Резервні копії

Перед кожним збереженням поточна версія копіюється в `data/.backups/`
(зберігаються останні 25). Кнопка **Історія** в панелі показує їх списком
і дозволяє відкотитися. Відкат теж спершу робить копію поточного стану,
тож його завжди можна скасувати.

Якщо панель недоступна, копії — звичайні JSON-файли: скопіюйте потрібний
поверх `data/projects.json` через FTP.

## Структура

```
lead-submit.php        приймає заявки з усіх форм сайту
data/
  services.json        дані блоку «Onze diensten»
  projects.json        дані проєктів
  partners.json        дані блоку «Onze partners»
  .backups/            автоматичні копії
admin/
  index.php            вхід і оболонка панелі
  api.php              завантаження/збереження/відкат
  lib/                 сесії, валідація, запис на диск
  assets/              стилі й логіка панелі
  config.php           створюється під час першого запуску
js/
  data.js              завантажує JSON для сайту
  main.js              рендерить послуги та проєкти
```
